実機とエミュレータの違い

項目	実機（スマホ）	エミュレータ
画面サイズ	1080×2400 px（物理ピクセル）、約 400×850 dp	1080×2424 px（物理）、420×924 dp
Pixel density / DPI	高い（例えば 420dpi）	エミュレータで固定される場合あり
Flutter logical pixels (dp)	実際の画面サイズにマッピングされる	設定通りの dp にマッピングされる
Camera.zoom の見え方	画面いっぱいに縮小表示される	Canvas サイズに対して縮小が小さすぎて目で見えにくい
タッチ座標	screen → world 変換が正しく行われる	同じ変換は行われるが、画面が小さいので縮小差が目に見えない

ポイントは Canvas の dp サイズに対して world サイズが大きすぎると、縮小されても見た目にほとんど変化がない ということです。

2️⃣ つまり何が起きているか

さっきのエミュレータで Camera.zoom = 0.459 の状態：

world = 896×1024 px

Canvas = 411×923 dp

見た目上は縮小されているはずだけど、dp が少ないため「ほぼ等倍に見える」

実機では、Canvas がもっと大きく（物理解像度に応じて）描画されるので、ちゃんと縮小された世界が表示される

タッチボタンも Stack + Positioned で画面固定なので、実機でも正しく動作する

3️⃣ まとめ

エミュレータで縮小が目に見えないだけで、Camera.zoom やタッチ処理は正しく動作している

実機では問題なく縮小される

エミュレータで「見える縮小を確認したい場合」は：

world サイズを一時的に小さくする

Camera.zoom を極端に小さくする

デバッグ用に枠線を描画する

💡 要は、今回のコードで 実機での動作は正常。
エミュレータ上で「縮小されていないように見える」のは dp サイズと画面密度の違い だけです。
